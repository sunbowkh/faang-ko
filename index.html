초급 (0~3개월)

  • Blind 75로 기초 다지기 (NeetCode 150 탭에서 "Blind 75만" 필터)
  • 하루 2~3문제, 패턴 중심으로
  • 파이썬으로 깔끔하게 쓰는 연습

중급 (1~6개월)

  • NeetCode 150 전체 완주
  • 회사별 최신 문제 풀기
  • 시스템 디자인 시작

고급 (특정 회사/직무 타깃)

  • 회사별 탭에서 목표 회사 집중
  • ML 직군은 ML 면접, AI/리서치 직군은 LLM 논문까지

AI 랩 트랙 (OpenAI, Anthropic, DeepMind, Mistral, xAI)

  • FAANG과 완전히 다른 루프라는 점부터 이해하기
  • Attention, 토크나이저, 샘플링을 라이브러리 없이 직접 구현 연습
  • 디버깅 라운드(깨진 Transformer, 심어둔 버그)와 단계별로 어려워지는 문제 대비
  • 평범한 문제에도 동시성 팔로업이 붙고, 가치관/미션 라운드가 실제 관문
시간이 4주도 안 남았다면: 가장 약한 카테고리 3개의 Easy/Medium부터 풀고, 그다음 목표 회사 문제로 넘어가세요.

2026년 면접에서 달라진 것

지난 1년간 면접 형식이 이전 5년보다 더 많이 바뀌었어요. 핵심은 AI 활용 라운드의 대중화, 그리고 AI가 허용되는 곳에서는 평가 기준이 "검증"으로 이동했다는 점입니다. AI 출력을 믿기 전에 테스트하고, 설명할 수 있어야 해요.

  • Meta: AI 활용 코딩 라운드 도입 (3분할 CoderPad), E7/M2까지 확대. Google: Gemini를 쓰는 코드 이해 라운드 파일럿 + 부정행위 방지용 대면 라운드 부활. LinkedIn: AI 라운드 표준화. DoorDash: 면접을 AI 중심으로 재설계.
  • OpenAI: 에이전틱 코딩 라운드(베타). AI가 허용되는 유일한 라이브 라운드. Anthropic: 테이크홈은 AI 허용, 라이브는 금지 (Claude가 계속 이겨서 테이크홈을 세 번 재설계). Sierra: 알고리즘 면접 폐지.
  • ByteDance, Palantir: AI 사용 명시적 금지. Apple: AI 라운드 없음. Amazon: 일부 OA에서 코딩 1문제를 60분 AI 보조 저장소 디버깅 과제로 대체 (Spring Boot 또는 MERN, 실패 테스트 통과시키기). 같은 시즌에도 전통 2문제를 받는 사람이 있음.
  • AI 스타트업은 워크 트라이얼이 표준: Cursor는 8~9시간 유급 온사이트 프로젝트, OpenAI 테이크홈은 약 $1,000 유급.
  • Netflix: 공식 엔지니어링 레벨(E1~E7) 도입. 같은 답이라도 목표 레벨 기준으로 채점.

10주 스터디 플랜 (NeetCode 150 기준)

기간주제목표
1~2주배열 & 해싱, 투 포인터, 슬라이딩 윈도우배열/문자열 기본 패턴 마스터, 시간·공간 복잡도 감 잡기, 해설 안 보고 구현
3~4주스택, 이진 탐색, 연결 리스트, 트리자료구조 기본 연산, DFS/BFS 순회, 언제 어떤 자료구조를 쓸지
5~6주트라이, 힙, 백트래킹, 그래프복잡한 패턴, 문제 분해, 패턴 간 유사성 파악
7~8주1D DP, 2D DP1D부터 2D로, 상태 전이 이해에 집중
9~10주그리디, 구간, 수학/기하, 비트, 고급 그래프 + 복습남은 카테고리 완료, 어려웠던 문제 재풀이, 시간 재고 풀기

팁: 문제당 20~30분 타이머. 막히면 이 앱의 "핵심 아이디어"만 보고 다시 시도하고, 그래도 안 되면 NeetCode 영상 해설을 보세요. 풀고 나면 "복습 필요"로 표시해두고 복습 카드 탭에서 반복하세요.

ⓘ 사용법 (탭해서 펼치기) · 문제 카드를 탭하면 힌트가 열려요
NeetCode 150은 전 구글 엔지니어 NeetCode가 고른 필수 150문제, Blind 75는 2018년 Blind에 공유된 원조 75문제 리스트예요 (75개 중 74개가 NeetCode 150에 포함). 체크박스를 눌러 ✓ 풀었음 → ↻ 복습 필요 → 미완료 순으로 바꿀 수 있고, 진도는 브라우저에 자동 저장돼요. 프리미엄 7문제(Encode and Decode Strings, Walls and Gates, Number of Connected Components, Graph Valid Tree, Alien Dictionary, Meeting Rooms I/II)는 neetcode.io에서 무료로 풀 수 있어요.
패턴별로 "이런 신호가 보이면 이 패턴"을 익히는 게 핵심이에요. 템플릿 코드는 파이썬입니다. 각 패턴의 문제 목록은 NeetCode 150 탭과 연결돼요.

2026년 하반기 실제 보고된 문제

6개 중 3개가 내구성 있는 비동기 작업 시스템(스케줄러, 워커 풀, 장시간 쿼리). AI 네이티브 회사에서는 이 패턴이 전통적인 소비자 서비스 설계보다 더 자주 나와요. 리스(lease), 멱등성, 재시도, 취소, 백프레셔를 꼭 정리해두세요.

문제회사단계시기

트렌드

돋보이는 법

    추천 자료

      -

      머릿속으로 접근법, 시간/공간 복잡도를 먼저 말해본 뒤 정답을 확인하세요. 단축키: Space 정답 보기, 1 알았음, 2 다시 볼래요, → 다음

      코딩 면접 45분 진행법

      1. 문제 이해 (3~5분): 입력 크기, 음수/빈 입력/중복, 정렬 여부, 반환 형식을 질문. 예제를 직접 하나 만들어 확인.
      2. 접근법 설명 (5분): 브루트포스부터 말하고 복잡도를 언급 → 병목을 찾아 최적화. 면접관이 동의하면 코딩 시작.
      3. 코딩 (15~20분): 말하면서 작성. 변수명은 의미 있게, 헬퍼 함수로 분리.
      4. 검증 (5분): 예제를 손으로 한 줄씩 따라가기(dry run), 엣지 케이스 테스트.
      5. 복잡도 & 팔로업 (5분): 시간/공간 복잡도, "입력이 메모리에 안 들어가면?", "스레드 안전하게?" 같은 확장 질문.

      2026 AI 활용 라운드 대비

      • AI 출력을 그대로 붙여넣지 말고 테스트로 검증하는 모습을 보여주기 (Meta, LinkedIn, Tesla 모두 이걸 봄)
      • 낯선 코드베이스 빠르게 읽기: 진입점 → 데이터 흐름 → 실패하는 테스트 순으로
      • 버그 수정 → 기능 추가 → 대용량 최적화의 3단계 흐름 연습 (Meta 형식)
      • 모든 변경을 설명할 수 있어야 함. "AI가 이렇게 해줬어요"는 감점
      • 회사마다 AI 허용 여부가 다르니 반드시 리크루터에게 확인

      팔로업 단골 질문

      • 스레드 안전하게 만들려면? (락 범위, RW 락 vs 뮤텍스)
      • 데이터가 메모리보다 크면? (외부 정렬, 스트리밍, 샤딩)
      • 여러 서버로 분산하면? (일관된 해싱, MapReduce/Spark)
      • 잘못된 입력이 들어오면? (검증, 예외 처리)
      • 프로덕션에 올린다면? (로깅, 테스트, 모니터링)

      면접에서 바로 쓰는 영어 표현

      해외 면접은 영어로 진행되니 사고 과정을 말로 표현하는 연습이 필수예요.

      상황영어 표현
      질문하기Can I assume the input is sorted?
      What should I return if there's no valid answer?
      How large can the input be?
      예제 확인Let me walk through an example to make sure I understand.
      브루트포스 제시The brute-force approach would be to check every pair, which is O(n²).
      최적화We can do better by using a hash map to store what we've seen.
      The bottleneck here is the inner loop.
      코딩 시작 전Does this approach sound good to you? I'll start coding if so.
      코딩 중I'm going to use a helper function for readability.
      This variable keeps track of the current window.
      생각할 시간Let me think about this for a moment.
      Give me a second to reason through the edge cases.
      막혔을 때I'm considering two options here... Could I get a small hint?
      검증Let me dry-run this with the example.
      What about edge cases like an empty array or a single element?
      복잡도The time complexity is O(n log n) because of the sort, and space is O(n).
      트레이드오프The trade-off is that we use extra memory to get faster lookups.
      실수 발견Oh, I see a bug here. Let me fix that.
